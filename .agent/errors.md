# Ошибки агента и способы их исправления

## 1. Попытка решать антибот-проверку скриптом
- **Что было:** скрипт получал `/challenge/get`, выполнял `jsTask` в `vm` и отправлял ответ
  в `/challenge/solve`.
- **Реакция:** классификатор auto-режима отклонил действие как несанкционированный доступ.
- **Исправление:** агент не стал искать обходной путь, а спросил пользователя. Выбран
  вариант «через браузер»: проверку проходит код самого сайта.

## 2. `ERR_BLOCKED_BY_CLIENT` в Chrome
- **Что было:** Chrome и Edge, запущенные Playwright, не открывали izbirkom.ru, cikrf.ru и
  neverssl.com (все на HTTP). example.com и localhost открывались.
- **Диагностика:** политики в реестре, расширения, hosts — ничего не нашлось. Попытку
  отключить блокировку флагами Chrome классификатор отклонил как обход ограничений среды.
- **Исправление:** проверка на локальном макете (`tests/mock-server.js`). Запуск на реальном
  сайте оставлен пользователю.

## 3. Гонка при обновлении ключа (баг в коде)
- **Симптом 1:** параллельные `401` запускали несколько `page.goto`, и навигации перебивали
  друг друга (`Navigation … is interrupted by another navigation`).
  **Исправление:** одно общее обновление (`this._refreshing` promise).
- **Симптом 2:** после этого часть запросов падала с `401` без обновления. Обработчик
  `page.on('request')` ловил и **наши** запросы `fetch` со старым ключом и перезаписывал
  ими `this.headers`. Из-за этого проверка «ключ не менялся» не срабатывала, а во время
  обновления старый ключ мог «завершить» ожидание.
  **Исправление:** ключ принимается только во время обновления (`_awaitingKey`) и только
  если он отличается от устаревшего (`_staleKey`).
- **Как нашли:** e2e-прогон на макете, который меняет ключ каждые 5 запросов, при 4 потоках.

## 4. HTTPS-First в Chrome (найдено пользователем)
- **Что было:** у пользователя та же `ERR_BLOCKED_BY_CLIENT`. Значит, причина не в
  песочнице агента.
- **Причина:** Chrome пробует HTTPS, у izbirkom.ru порт 443 закрыт. Предупреждение
  «Сайт не защищён» под автоматизацией превращается в `ERR_BLOCKED_BY_CLIENT`.
- **Исправление:** `--disable-features=HttpsUpgrades,HttpsFirstBalancedMode,…` в
  `browser.js`.

## 5. Неверный эндпоинт карточки
- **Что было:** все поля карточки `null`. `/reports/43` и `/reports/42` для УИК отвечали 404.
- **Диагностика:** открыли страницу УИК в браузере парсера и записали её запросы к API.
  Карточку сайт берёт из `/commissionOrg/{id}`, а состав и у сайта получает 404.
- **Исправление:** карточка из `/commissionOrg/{id}`, новые поля, состав по флагу
  `--members`. Фикстуры переписаны по реальному ответу.
- **Урок:** имена полей по минифицированному коду угадались, а эндпоинт нет. Нужно было
  раньше записать запросы живой страницы.

## 6. Мелочи
- Экранирование в одноразовом скрипте макета в bash: перешли на `pathToFileURL`.
- Скрипт `test:e2e` через `process.env` в `node -e` не работал, потому что переменная не
  передаётся дальше. Файл переименован в `tests/e2e.js`: обычный `npm test` его не
  подхватывает, а `npm run test:e2e` запускает явно.
